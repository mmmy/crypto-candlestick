# 绘图价格警报验证记录

2026-10-05，Windows x64，本机 Rust stable，Release 对比使用同一测试进程的隔离 `sqlite::memory:` 数据库。未调用任何真实交易接收端，未修改业务 K 线数据库。

## 初版 Release 相同场景（尚未接入 tickSize）

命令：`cargo test --release --test price_alert_tests release_index_benchmark -- --ignored --nocapture`。

固定 1000 条同品种水平规则、`extend=both/frequency=once`，10000 次价格 900/901 交替，全部规则价位 1000..1999，两个实现都没有触发事件。旧路径每次读取/解码全部活跃规则并更新侧别；新路径复用价格索引和候选缓冲。

| 实现 | 10000 样本累计 | 每样本 |
| --- | ---: | ---: |
| 新内存索引 | 1.4539 ms | 0.145 µs |
| 原逐样本 SQLite 查询 | 106.3961919 s | 10639.619 µs |

这个场景的时间下降来自移除 SQL、1000 条配置解码和无穿越时的全规则扫描。它不测量成交触发时的事务、HTTP、磁盘 I/O、趋势线扫描、图表输入响应或整机 CPU/内存峰值；不能把比值推广为所有场景的加速。基准时本机同时进行其他工程编译，数据是一次实际测量，适合作为此场景消除 I/O 的证据，不是稳定的延迟上界。水平正常行情不用数据库查询或分配候选容器；首次建立基线和实际触发允许配置/事件分配。

## 语义与生命周期

`tests/price_alert_tests.rs`：触碰与跨越、单次触发、TV 字段类型、有效方向、移动首次观察、触发后重设、样式不重设、暂停、过期与 null 清除、有限时间范围、趋势线每样本线价、乱序/重连、CAS 与操作恢复、v1 持久清空及旧事件回执、删除保留 cancelled 历史、隔离文件数据库重启、旧代回执、8 并发和关闭取消。

`price_alerts::persistence_tests`：注入 SQLite 事件插入失败，验证交易状态/事件/outbox 同一事务回滚，恢复后仍提交原始穿越，且并发移动不能覆盖未提交的穿越；另验证投递回执等待运行时锁时关机仍可取消。

完整 `cargo test -j 1` 覆盖原有行情恢复、周期聚合、HTTP、指标、信号引擎和存储回归。使用 `-j 1` 是因为首次默认并行编译在本机出现内存不足；该编译资源失败不被计为测试通过。`cargo fmt --check`、`cargo clippy -j 1 --all-targets` 和 `cargo build --release -j 1` 是最终检查；仓库原有 large_enum_variant、too_many_arguments 和两个 type_complexity Clippy 警告单独保留，新增价格警报代码没有新增警告。
